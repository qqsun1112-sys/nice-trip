# WELCOME50 第一階段端到端驗收案例（測試環境用）

狀態：待執行。正式官網、LINE、Supabase 正式資料庫未變更。

## 驗收順序
1. 確認獨立 Supabase 測試專案／分支，並取得任何可能產生費用的同意。
2. 測試資料庫套用優惠欄位 migration，確認所有活動 welcome50_enabled 預設 false。
3. 測試用 city 活動指定 welcome50_enabled=true；其他 city 活動仍 false。
4. 先測「無優惠碼」全流程，確認票價、訂單編號、通知信、匯款回報、取消及名額釋出不變。
5. 再測有優惠碼的完整流程，確認折扣在後端重新計算，並且訂單、信件、後台金額一致。
6. 測試異常與併發情境後才進行正式上線審查。

## 必須拒絕優惠且不建立訂單
- 無效優惠碼、優惠期限外、免費票、非 city 服務、未指定的 city 活動。
- 同時要求其他優惠券、活動停止報名、名額不足、人數超過上限。
- 前端竄改 unit_price、total_amount、discount 或 eligible=true。
- 失敗時不得偷偷改用原價送出，需請使用者自行清除優惠碼並確認原價。

## 回歸測試
- 一般報名（未輸入優惠碼）須完全維持原本流程。
- 早鳥票屬既有票價，並非自動等同「其他優惠券」；是否適用 WELCOME50 需依正式規則確認。
- 匯款末五碼回報、後台核款、Email、取消驗證碼、名額釋出。
- 同一活動同時送出兩筆訂單時，容量不超賣；兩次點擊送出不可重複建立訂單。
- 手機版欄位顯示及金額明細，錯誤提示須可讀。
- 舊資料原價及舊通知格式不可因 migration 而損壞。
