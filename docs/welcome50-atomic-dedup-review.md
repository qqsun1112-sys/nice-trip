# WELCOME50 同人同場防重複：交易安全設計

**狀態：獨立分支草案，未執行 migration、未修改正式 Supabase。**

## 簡化規則
- 同一位參加者同一場指定付費城市故事行旅，僅可享一次 WELCOME50。
- 不同場次可分別使用；多人報名逐位查驗，每位符合資格者折 NT$50。
- 不串接 LINE，不需要 LINE 身分識別。
- 同一筆報名如有任何人已使用優惠，**整筆暫停提交並顯示需要調整**；不可默默以原價替部分人報名。
- 取消後**暫不自動恢復**已使用資格，以防反覆取消重領；正式政策需經使用者核准。

## 資料庫保護
使用 `welcome50_uses(event_slug, identity_hmac)` 唯一限制，而不是「先查是否用過，再新增」兩個分開的操作。並發提交只有一筆可成功，另一筆會因唯一限制失敗且整筆交易回滾。

`identity_hmac` 由受保護的伺服器端金鑰產生，禁止直接存明文身分證號、姓名拼接或無金鑰雜湊。前端不送 identity_hmac；只送依法告知、確有必要的個人資料。不同證件類型與非投保者須先定義驗證政策，不得為折扣而強制收集不必要的保險資料。

**關鍵依賴：** 目前 `create_registration_atomic` 只插入一筆 registrations。正式版必須改為單一資料庫交易，連同 participants、welcome50_uses 一次寫入；僅建立唯一索引而沒有整合 RPC 不會自動生效。

## 安全驗收
1. 兩個並發請求，同場同人同碼：只能一筆成功，另一筆回傳可理解的「已使用」提示。
2. 同人不同場：兩筆皆可享優惠。
3. 同場多人其中一人已使用：拒絕整筆折扣提交，不能靜默扣除或以原價送單。
4. 任一步驟錯誤時，報名、名額、折扣使用紀錄全部回滾。
5. 一般無碼報名不寫入優惠使用紀錄，原有匯款、通知及取消流程維持。
6. 僅伺服器受權角色可讀取使用紀錄；個資不得出現在網站頁面、分析事件或錯誤訊息。
7. 保險不申請者與未提供合法身分識別者的優惠資格，需明確訂定，不能猜測。

## 注意
此 SQL 僅為 schema 設計，不是可直接部署的完整功能。正式上線前需依實際 registrations 主鍵型別、RLS/權限、既有取消邏輯與 RPC 稽核後修正。
