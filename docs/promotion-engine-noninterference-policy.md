# 美遊記通用促銷引擎｜隔離設計與不可破壞報名原則

**狀態：設計規格，未部署。** 任何程式碼、資料庫及 LINE 正式變更須另行核准。

## 不可妥協的基本規則
1. **一般報名優先**：沒有優惠資格、不輸入優惠碼、或優惠系統不可用的訪客，仍可依原有票價完成報名、匯款回報、後台確認、取消及通知。優惠服務不可成為一般報名的必填依賴。
2. **顧客明確選擇**：有優惠者可選擇使用；無效、過期或不可用時顯示原價及原因，顧客確認原價後才能提交；禁止靜默改價或將原價當優惠價。
3. **每個方案獨立期限**：活動開始、發放截止、兌換截止、時區 Asia/Taipei，並明確區分「報名日期」與「出發日期」限制。
4. **多方案隔離**：年終慶、週年慶、加入好友、好友推薦等各有代碼、折扣類型、資格、使用次數、適用服務與票種、併用政策、預算上限及啟停狀態。
5. **伺服器權威**：前端試算不可信；最終金額、資格及核銷由後端資料庫交易決定。無優惠的舊路徑不變。
6. **不降低既有安全性**：沿用活動名額鎖、報名期限、付款及通知規則；不可讓折扣引入繞過驗證、重複核銷、負金額、冒用身分。
7. **資料稽核**：保留原價、折扣、實付、活動代碼、核銷識別及異動歷程；最小化保存個資，優惠權益以不可逆的內部識別表示。
8. **功能旗標與回退**：促銷引擎獨立開關，預設關閉；關閉時一般報名完全正常；不能以停用促銷功能刪除既有合法報名或金額。

## 建議資料模型（測試環境設計）
- `promotion_campaigns`：`code`、`name`、`kind`、`start_at`、`issue_end_at`、`redeem_end_at`、`timezone`、`enabled`、`discount_type`、`discount_value`、`eligible_services`、`eligible_ticket_codes`、`stacking_policy`、`max_uses_per_person`、`campaign_budget`、`event_date_rule`。
- `promotion_entitlements`：活動代碼、經驗證的使用者識別、取得證據、到期時間、使用狀態。
- `promotion_redemptions`：核銷者、報名、折扣額、原子交易結果及取消處理歷程。
- `registrations` 保留原有欄位，新增原價及折扣快照；`total_amount` 永遠代表實際應匯款金額。

## 服務分層
- `submit-registration` 仍是報名唯一入口；**沒有選優惠時完全不需呼叫 LINE、推薦系統或促銷身分驗證服務**。
- 有選優惠時，報名前先預檢；提交時後端再次驗證。優惠不可用則回傳專用 `promotion_unavailable`，不建立報名、不佔名額，提示「可不使用優惠，以原價報名」；只有使用者確認後才重新提交原價。
- 促銷服務中斷時，普通報名必須仍可執行；不要默默忽略使用者已選優惠的折扣。
- 功能旗標預設 `false`，開啟只作用於選用優惠者；每個促銷方案可獨立停用。
- 一筆報名多人時，折扣權益與受惠人數須一致；不得憑單一優惠序號自動折抵所有參加者。

## 驗收矩陣
| 情境 | 預期 |
|---|---|
| 不輸入優惠 | 正常報名，原價 |
| 未符合資格 | 清楚告知，選擇原價報名 |
| 優惠尚未開始／已過期 | 不可折扣，但正常報名不受影響 |
| 促銷服務逾時／錯誤 | 選優惠者可明確改原價；其他人正常報名 |
| 已用過的權益 | 拒絕重複折扣；原價報名可用 |
| 同時推出年終慶與好友禮 | 依併用規則，不得擅自重複折扣 |
| 管理者關閉單一促銷 | 其他促銷及正常報名不受影響 |
| 免費票 | 不折抵，不影響免費報名 |
| 已完成報名、通知、匯款回報、取消 | 原有流程回歸測試全部通過 |

## 優惠期間
「美遊記・好友同行禮」目前規劃 2026-10-20 至 2026-12-31；後續年終慶、週年慶、加入好友禮須各自設定獨立起迄日期，不共用硬編碼期限。

## 發布關卡
須先在隔離測試環境完成優惠與**無優惠**兩組全流程驗收；提供測試證據及回退方案，使用者再次明確同意後方可發布。
