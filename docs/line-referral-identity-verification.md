# LINE 好友推薦資格驗證｜隔離設計（尚未串接）

## 核心限制
- LINE Login / LIFF 可以在正確設定及驗證 ID token 後識別使用者，但**不能單憑登入證明已加 LINE 官方帳號好友**，也不能證明「這位好友由誰推薦」。
- 推薦網址上的 `ref` 參數只是推薦來源線索，不能直接發券。
- 需要 LINE 官方帳號 Messaging API webhook 的 `follow` 事件、簽章驗證與可靠儲存，才能建立可稽核的新增好友紀錄。若使用者先前已是好友、解除封鎖後重新加入，或事件無法確認，必須依活動規則排除或人工審核。
- Messaging API 與 LINE Login 若為不同 channel，須核對 provider / userId 可否可靠對應；不可預設跨 channel ID 一定相同。
- 目前沒有可證實的 LINE OA 內建「推薦雙方自動各領 NT$50」功能；此規格是自建活動邏輯，不代表 LINE 官方優惠券本身具備此功能。

## 建議核發流程
1. 推薦者以 LINE Login 登入專用活動頁，經 OIDC 驗證後取得受保護的內部 `subject_key`，系統簽發短效、不可竄改的推薦邀請 token。
2. 新朋友從推薦連結進入，經 LINE Login 取得本人身分；不得是推薦者本人。
3. 引導新朋友加入官方帳號；後端接收並驗證 LINE webhook 簽章，僅將已確認的首次 `follow` 事件視為新好友候選。
4. 將登入身分與 webhook 事件在可信的 provider/channel 規則下綁定，確保推薦邀請發行時間早於首次追蹤事件；一位新好友只能綁定一位推薦者。
5. 完成反濫用檢查後，對推薦者與新好友各核發一筆 NT$50 權益；每人活動期間限一次，已取得權益者不得再次取得。
6. 報名時本人再次登入／驗證，由後端查詢本人未使用的權益；與報名資料庫同一交易核銷。禁止使用客戶端傳入的金額或未驗證的 `userId`。
7. 取消、逾期、退款後是否恢復權益，須先核准政策；不得預設恢復。

## 必須確認的 LINE 設定
- LINE Login channel 的 Callback URL、LIFF Endpoint URL、scope（僅最低必要權限）。
- Messaging API webhook URL、Use webhook 設定、事件驗證、channel secret 安全儲存與輪替。
- LINE Login 與 Messaging API channel 是否同 provider，並實測身分關聯。
- 隱私權告知、資料保存期限、退訂與刪除政策。
- LINE 追蹤事件是否有足夠歷史資料辨識「首次加入」；若沒有，不得宣稱可自動排除所有舊好友。

## 必須通過的測試
- 有效簽章的首次 follow + 有效推薦 + 不同身分 => 候選核發。
- 無效簽章、重播事件、無 follow、未登入、同一人推薦自己 => 拒絕。
- 舊好友重新追蹤、解除封鎖重新加入 => 依規則拒絕或待人工審核。
- 一位新朋友點多個推薦連結 => 僅首筆合格且已鎖定的推薦關係有效。
- 同一推薦者推薦多位新朋友 => 推薦者只能獲得一次 NT$50。
- 兩人同時領券、同時報名核銷 => 唯一索引與交易鎖避免重複核銷。
- 未通過 LINE 身分關聯檢查 => 不發券。
- 活動期限以台灣時間 2026-10-20～2026-12-31 為準；須確認活動是否允許到期日當天的報名、或要求活動出發日也在期限內。

## 部署界線
本文件只存在 GitHub feature 分支。沒有設定 LINE webhook、沒有更新正式 Supabase、沒有發券或更動官網。部署需獨立測試環境與使用者再次確認。
