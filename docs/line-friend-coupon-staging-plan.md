# LINE 好友同行禮｜隔離測試規格（未上線）

狀態：設計與測試準備。此分支不得直接部署；不可在正式 Supabase 執行遷移或修改既有活動資料。需另行取得正式發布確認。

## 已核實的現況（2026-10-20）
- `activity-register.html` 由 `site_activities.ticket_options` 讀取票種，前端計算 `unit_price × quantity` 僅供顯示。
- 正式 Supabase Edge Function `submit-registration` 在伺服器端重新取得票種，計算 `unit_price × quantity`，建立 `registrations` 紀錄，並以該金額寄發匯款通知。
- `registrations` 已有 `ticket_code`、`unit_price`、`total_amount`，目前沒有優惠券／推薦關係欄位或核銷資料表。
- `report-transfer`、後台收款確認及取消流程須一起驗證。
- LINE 好友推薦關係不能由顧客自行輸入文字或轉貼連結直接視為驗證成功；需明確的推薦來源證據或人工審核機制。

## 目前採用的需求（仍待 LINE 平台能力核對）
- 活動名稱：美遊記・好友同行禮。
- 發放／推薦期間：2026-10-20 至 2026-11-19；折抵使用期限：2026-12-31 前。
- 推薦者及受推薦者各獲得 NT$50 折抵權益，限城市故事行旅付費票，公益免費票不可折抵。
- 每位合格使用者限一次；與既有優惠票併用是本輪確認的建議，但須先檢查票價下限與活動規則。
- 同筆多人報名不得憑單一序號自動折抵全部人；每位實際折抵者須獨立驗證資格。
- 未確認推薦關係與核銷前，不得宣稱已發放或可自動使用。

## 待實作（僅在隔離測試環境）
1. 建立優惠權益表與核銷流水帳：隨機不可猜測 token、資格類型、推薦關係證據、發放時間、有效期、狀態、使用報名編號；限制唯一使用者及單次核銷。
2. 後端於同一資料庫交易中驗證權益、活動服務、票種、數量、截止時間、使用者資格與重複使用；確保折抵金額不大於應付額。
3. 報名紀錄另存原價、折扣、實收應付、權益代碼／核銷識別碼，確保匯款通知、後台、報表金額一致。
4. 前端只顯示試算與驗證狀態，不信任客戶端傳入的折扣額；提交時顯示伺服器確認的最終應匯款金額。
5. 取消、逾期與退款的權益恢復規則；處理重試、重複送單、並發核銷與信件發送失敗。
6. 以獨立 Supabase 測試專案及測試郵件驗證，不使用正式報名者個資或實際寄信。

## 驗收案例
- 正常單人 NT$750 -> NT$700。
- 符合資格的其他付費票折抵 50 元，且不低於零。
- 公益免費票不適用。
- 兩人只有一人具備權益，只折抵 NT$50；不得折抵 NT$100。
- 已使用、過期、無效、冒用、非城市行旅、超過發放／兌換期限均拒絕。
- 兩筆同時使用相同權益，只允許一筆成功。
- 報名成功頁、待匯款信、後台報名與收款、Excel 報表金額完全一致。
- 取消／逾期後依核准政策處理是否恢復權益。
- 一般票、早鳥、會員、團體票原有流程不受影響。

## 正式發布關卡
須先核對 LINE 官方帳號優惠券與推薦機制的實際功能、完成測試報告、確認活動條款，取得使用者再次明確批准後，才能部署前端、資料庫、Edge Function 或發布 LINE 優惠券。
